## Безопасность  

Поскольку проект --- это дневник пациента, безопасность здесь критически важна с первого дня. Данные о здоровье людей в России защищаются законом ФЗ-152 «О персональных данных». Как только в вашей базе данных появляется связка «Имя/Телефон + Показатель здоровья (давление, диагноз)», эта информация юридически становится специальной категорией персональных данных.  Вот что это значит для  стартапа на практике: 

## 1. Бесплатный хостинг и безопасность (Важное ограничение) 

Выкладывать проект на зарубежные бесплатные сервисы (Render, Railway) можно только для тестирования с вымышленными данными (например, «Иван Иванов, давление 120/80»).  
* Причина: По закону РФ персональные данные россиян обязаны храниться на серверах внутри России. 
* Решение для MVP: Пока вы тестируете интерфейс внутри команды --- пользуйтесь бесплатным хостингом. Как только приглашаете первого реального пациента --- сразу переезжайте на платный российский хостинг.  

## 2. Защита данных на старте (Что должен сделать питонист) 

Пока не наняли специалиста по безопасности,  Python-разработчик должен внедрить базовые технические правила:  
* Шифрование паролей: Пароли пользователей никогда не должны храниться в базе данных в чистом виде (Django делает это автоматически из коробки). 
* HTTPS-протокол: Сайт должен работать по защищенному соединению (с замочком в адресной строке). Это бесплатно, хостинги дают такой сертификат автоматически. Без него данные, которые пациент вводит с телефона, могут перехватить в публичном Wi-Fi. 
* Разделение данных: Лучше хранить ФИО пациента в одной таблице базы данных, а его медицинские показатели --- в другой, связывая их только через случайный ID. Если базу взломают, злоумышленники увидят просто список цифр без привязки к конкретным людям.  

## 3. Юридическая сторона На вашей первой страничке в интернете обязательно должны быть две кликабельные ссылки внизу:     

1. Политика конфиденциальности (текст о том, как вы обрабатываете данные).    

2. Согласие на обработку персональных данных (галочка, которую пациент нажимает при регистрации). Без этой галочки собирать данные нельзя.  Переходить к реальной защите по ФЗ-152 (покупка серверов в специальном защищенном контуре) нужно, когда проект начнет зарабатывать.  В России есть бесплатные варианты для старта, но с ними есть важный юридический нюанс. Полноценный бесплатный хостинг для Python-приложений (как Django) в РФ найти сложно, но крупные российские облачные провайдеры предлагают бесплатные гранты для стартапов или бесплатные тестовые периоды. 

## Вот лучшие варианты, чтобы развернуться сразу в РФ и не переезжать: 

 1. Гранты для стартапов (Самый выгодный путь) Крупные компании дают новым проектам виртуальные деньги, которых хватает на несколько месяцев или даже год бесплатной работы:  

* Yandex Cloud (Программа Cloud Boost): Выдают гранты до нескольких сотен тысяч рублей для ИТ-стартапов. Этого хватит, чтобы полностью бесплатно держать сервера, базы данных и защищенный контур. * MTS Web Services (MWS) или VK Cloud: У них тоже есть программы поддержки стартапов, где дают бонусные балансы на тестирование и запуск MVP.  

 2. Тестовые периоды и ультра-дешевые тарифы Если грант получать долго, можно использовать минимальные тарифы, которые стоят как чашка кофе:  * Timeweb Cloud / Selectel: Иногда дают приветственные бонусы при регистрации (около 300--500 рублей на счет). На них можно бесплатно тестировать проект первый месяц. Далее сервер будет стоить около 150--250 рублей в месяц, что для стартапа фактически бесплатно, но при этом вы сразу юридически чисты перед ФЗ-152.  

 
 Как поступить правильнее всего? 
Зарегистрироваться  в Yandex Cloud или Timeweb Cloud. Для первых тестов хватит приветственных бонусов. Если проект начнет расти, подадать заявку на грант для стартапов прямо внутри их личного кабинета, либо начать платить минимальные 200 рублей в месяц.
